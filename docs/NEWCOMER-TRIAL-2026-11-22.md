# 新人全流程安装试验记录（2026-11-22）

试验对象：`ai-house-kit` 0.2.0（提交 `11503a5`）。
试验设定：一位**不懂代码的新手**，只对 AI agent 说一句「帮我装好跑起来」，自己只会最后打开浏览器。
环境：Linux 容器，root，Python 3.13，Docker 29（守护进程需手动启动）。
模型：`gpt-4o-mini`（真实 OpenAI 接口）；另用本地模拟接口和无 Key 演示模式做对照。

## 结论

- **安装本身能一次走通**：按 README 方式一，克隆 → 安装 → `init` → `doctor` → `up` 共约 10 秒，不改源码。方式二（Docker Compose 单容器）也能起。
- **填了 Key 之后，能聊、能写日记、能记忆，但有三处会让新手觉得「坏了」的实质问题**（见「阻断与高优先级」）。其中最重的是：接入真实模型后住客整夜不睡、白天长时间发呆，而无 Key 演示模式反而正常。

## 阻断与高优先级

### 1. 接入真实模型后住客不睡觉、白天长时间发呆

- 现象：`gpt-4o-mini` 下推进三个虚拟日，事件表里没有任何一次 `sleep`，没人换睡衣；例如奈尔（就寝 23:00）凌晨 1–4 点还在客厅喝茶、做家务。白天 08–11 点、13–17 点没有任何事件，六人都在卧室「发呆」，第三天早饭没人做。
- 对照：无 Key 演示模式下同样的推进方式，早饭、午饭都按时做了。
- 相关记录：`decision_points` 中出现 `answer_unusable`、`model_error:KeyError`、`refused:bad_duration`、`refused:unknown_recipe`、`unresolved_previous_call → degraded`。
- 根因与修复建议：见文末「不睡觉问题诊断」。

### 2. 「帮忙买 2 个鸡蛋」的采购闭环在真实模型下不成立

- 现象：两次请求，两次都没有采购。第一次模型调用 `record_promise` 时没给 `item`，约定 24 小时后 `expired`；第二次给了 `item: "鸡蛋"`（中文名而非 ID `egg`），约定一直 `open`，没人出门。
- 根因：`world-kernel/worldkernel/intents_lite.py` 的 `enqueue_chat` 只在模型**没有**返回任何约定时才走 `_detect_errand_item` 规则识别；模型一旦返回了约定（哪怕没带食材 ID），规则兜底就被跳过。工具说明里只写「食材ID（可选）」，没有列出可用 ID。
- 结果：README 首屏宣传的闭环，在演示模式（规则识别）下成立，填了 Key 反而失效。
- 建议：对模型返回的 `errand` 约定，缺 `item` 或 `item` 不在词表时，用原话再跑一次 `_detect_errand_item`，并把中文名映射回 ID；或在工具 schema 里用 `enum` 列出食材 ID。

### 3. GPT-5 系列模型全部连不上，报错看不懂

- 现象：模型名填 `gpt-5`、`gpt-5-mini`、`gpt-5.5`，测试连接返回 `HTTPError: HTTP Error 400: Bad Request`。
- 根因：`src/ai_house/chat_agent.py` 固定发送 `max_tokens` 和 `temperature: 0.7`，这些模型要求 `max_completion_tokens`。接口返回的具体原因（`Unsupported parameter: 'max_tokens'`）被丢弃。
- 影响：新手从 OpenAI 模型列表里挑一个较新的模型就会卡住，且无从判断是 Key 错、模型名错还是别的。
- 建议：收到 400 且提示 `max_tokens` 不支持时改用 `max_completion_tokens` 并去掉 `temperature` 重试；把接口返回的 `error.message` 原样显示给用户。

### 4. 编造的内容会写进长期记忆，并在之后盖过真实事实

- 现象：房主私聊告诉奈尔「我对花生过敏」。之后在群聊里问「谁知道我对什么过敏」，奈尔和艾莎都答「坚果过敏」，奈尔还说「布丁可能是艾莎吃的，她之前提过想尝」（均无依据；群聊提示词里确实没有私聊内容，所以这是编造而非泄露）。
- 这些话随后被记忆整理写成群聊域的 `fact`。次日私聊再问，提示词里同时注入了正确的「花生」和编造的「坚果」，奈尔回答「你对坚果过敏」。
- 建议：记忆整理时，室友自己说出的「我记得……」类陈述不应作为事实入库，或需有房主原话作证据（`src` 指向房主的那一行）才允许 `kind=fact`。

## 需要 agent 绕路的问题

| 现象 | 对新手的影响 | 建议 |
|---|---|---|
| `ai-house init` 生成了令牌但不显示，也不说 `.env` 的完整路径；登录页只写「.env 中的 AI_HOUSE_OWNER_TOKEN」 | 新手不会找隐藏文件，卡在登录页 | `init` 末尾打印 `.env` 绝对路径；增加 `ai-house token` 命令；登录页说明文件位置 |
| `ai-house up` 前台运行，README 没说关掉终端服务就停，也没给后台运行方法 | 关窗口后「网页打不开了」 | README 加一段常驻运行说明，或提供 `up -d` |
| 端口被占用（重复执行 `ai-house up` 很常见）时抛出 Python 堆栈 `OSError: [Errno 98]` | 新手看不懂 | 捕获后提示「8780 已被占用，可能小屋已经在运行」 |
| `ai-house init --pack life1` 抛出堆栈 `FileNotFoundError: WorldPack directory not found: life1` | README 把 `life1` 称为示例包，但命令行只认 `indie-studio-3` | 支持 `life1` 这个名字，或给出友好提示与可用列表 |
| README 只写 `pip install -e ".[dev]"`，没提虚拟环境 | Debian 12 / Ubuntu 24 / Homebrew 的系统 Python 会报 `externally-managed-environment`（本次环境为 root，未触发，未实测） | 首选步骤改为先建 venv；新手不需要 `[dev]` |
| README 方式二没有提示先确认 Docker 已启动 | `docker compose up` 直接报连不上 `docker.sock` | 加一句 `docker info` 自检 |
| 打开晴空都桥后默认没有任何人会进城（`WORLD_KERNEL_CITY_PLANS` 默认关），手动出门接口要求室友此刻「在客厅且空闲」，否则返回 `CITY_DEPARTURE_NOT_IDLE_AT_LIVING` | 新手开了城市功能却看不到任何变化 | README 的城市段落写明还需要哪个开关；错误提示改成人话 |

## 小瑕疵

- 快进会把小屋切换到虚拟时钟；重启后时钟回到真实时间，而日记、小结已经写到了「未来」的日期。本次快进到 11-24 后重启，时钟回到 11-22。
- 第一条聊天回复用了 15 秒：聊天请求里同步等待了另外 5 位室友各一次生活决策调用（每次约 6000 token）。
- 日记要求 80–200 字，实际普遍超长并在句子中间被截断（`max_tokens` 上限）；内容里有事实清单之外的修饰（「大家都说味道不错」「分享读书心得」）。
- 「记得房主对花生过敏」被记成 `cook` 类约定，当晚做了豚汁就被标为 `completed`。
- 各子命令的 `--help` 只有参数名，没有说明文字。
- 没有免令牌的健康检查接口（`/api/health`、`/api/status` 均 404）。
- Docker 容器日志里打印的访问地址是 `http://0.0.0.0:8780`，与宿主机实际发布的端口不一致。
- 首页「小屋群聊」卡片里，室友名字和时间被挤成竖排。
- 首页没有常驻的「当前是演示模式」提示。
- 小屋时间固定为日本时间，界面没有说明。
