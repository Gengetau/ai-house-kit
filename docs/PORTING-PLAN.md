# 功能移植方案（草案，待确认）

日期：2026-11-22　状态：**草案，尚未批准，未开始实施**

本文回答一个问题：维护者自用的私有部署（下称“私有端”）里已经有很多能力，怎样把它们变成新人装完 kit 就能用、且适合开源的可配置功能。

本文只写能力和做法，不含私有端的路径、账号、人设和基础设施细节。

## 1. 结论

1. **内核已经对齐，差距在内核之外。** kit 的 `worldkernel` 包与私有端几乎逐模块一致。私有端多出来的是内核外的一层：通道桥（工具、主动发言、发送护栏、模型链路）、记忆的证据与泄露防护、完整的约定系统。
2. **kit 现在的插件机制承接不了“可配置的开源插件”。** 必须先补底座，再搬功能。
3. **搬行为，不搬代码。** 私有端的通道桥是约 8 千行的单文件，绑定了另一套 agent SDK 和本机环境；kit 是标准库单进程。以私有端的测试为规格，在 kit 里重写。
4. **QQ 协议端不重做。** 现成的 OneBot 端可以与 kit 并排运行，kit 只负责把自己的 OneBot 插件做可靠。
5. **长期把方向反过来**：kit 当上游，私有端变成“kit + 私有覆盖层”。否则每次移植都是一次性的，两边会继续分叉。

## 2. 依据

三路只读调查的结果（2026-11-22）。

### 2.1 kit 现状

| 项 | 现状 | 位置 |
|---|---|---|
| 插件配置 | 插件不能声明配置项、默认值、密钥标记；各自在 `from_env` 里解析环境变量 | `src/ai_house/plugin_api.py`、`builtin_plugins/onebot_ws.py:159-195` |
| 启用开关 | 扩展、通道、provider、工具四个轴各有各的规则，没有统一开关 | `plugin_api.py:142-155`、`daemon.py:112,134-138` |
| 加载隔离 | 第三方包加载报错会让整个进程起不来 | `plugin_api.py:130` |
| 扩展点 | 插件不能注册 HTTP 路由、控制台页面、独立的周期任务 | `daemon.py:1438-1757`、`web/js/pages/` |
| 工具 | 工具函数拿不到说话人、住客、作用域；第三方包不能提供工具 | `daemon.py:622,666-676`、`plugin_api.py:85` |

| 健康检查 | 没有 | — |

### 2.2 私有端有、kit 没有的能力

按可移植性分三级。**A**：纯逻辑，标准库即可。**B**：需要外部服务，但有公开等价物。**C**：只对私有资产有意义，或不适合放进公开仓库。

| 能力 | 分级 | 规模 | 说明 |
|---|---|---|---|
| 统一发送门（上限、静默时段、发送账本、结果不明即挂起） | A | S–M | 有完整测试，可作为规格 |
| 消息状态机（入站持久化、成功后确认、聚合防抖、分条气泡） | A | M | 上游开源 QQ agent 的核心设计，思路可直接借鉴 |
| 群聊行为（回复概率、连发上限、闭麦、睡眠静默） | A | S | 私有端约 180 个环境变量，需要收敛 |
| 主动发言（时间窗口、日上限、最小间隔） | A | M | 依赖出站通路 |
| 记忆证据层（召回引用原话、相对日期换算） | A | M | 私有端仍是默认关闭的试点，稳定性待确认 |
| 泄露防护（私聊内容不在群里复述） | A/B | S | 有向量服务时更准，没有时退化为字面重叠 |
| 完整约定系统（证据闸、多人共同计划） | A | M | kit 的 `intents_lite` 是它的简化版 |
| 模型链路（按配额和故障切换、限流） | A | M | 只移植切换逻辑，不移植中转代理 |
| 提醒、无状态小游戏 | A | S | |
| 用量账本 | A | S–M | 改为在模型层直接记录每次调用 |
| 备份（SQLite 在线备份、校验、保留期） | A | S | |
| 看图、看视频 | B | M | 任意 OpenAI 兼容的多模态端点 |
| 语音转文字、语音合成 | B | M | 语音解码需要可选依赖 |
| 文生图 | B | M | 只保留通用调用，留“自带引擎”接口 |
| 联网搜索 | B | S | |
| 表情包库（检索与发送） | B | S | 只带可署名的公开素材 |
| 相册、日记配图 | B | M | 隐私范围规则需重新设计 |
| 按住客选模型 | A | S | 私有端“一人一模型”的开源等价物 |

### 2.3 不移植

| 项 | 原因 |
|---|---|
| 真实账号的空间动态、收藏表情同步 | 依赖真实账号 |
| 需要登录凭据或成人内容的抓图功能、搜书发书 | 内容与合规风险 |
| 私人云盘画廊、模拟器手机与电视 | 私人资产 |
| 本地 LoRA 与专属声线 | 私人资产；只保留“自带引擎”接口 |
| 协作与巡检 agent、API 中转代理 | 私人运维 |
| 私有表情包素材 | 版权 |
| 内核之外的旧世界控制器 | 私有端自己也处于向内核过渡的阶段；kit 直接以内核为准 |
| 私有端的大控制台 | 强依赖容器编排；只借鉴思路（日记书架、记忆分页、用量页） |

### 2.4 共同依赖

私有端的记忆、约定、世界、通道桥都依赖同一个身份层，它只按 QQ 号认人。这一层不先在 kit 里抽象出来，上面几项都搬不动。

## 3. 原则

1. **一个能力一个插件。** 插件自带清单：配置字段、类型、默认值、是否密钥、依赖什么。
2. **默认关闭，未配置时安静降级。** 不报错，不影响其他功能。沿用现有演示模式的思路。
3. **网页里能配完。** 控制台按清单自动生成表单，密钥只回显掩码。
4. **核心保持标准库。** 需要第三方包的能力走可选依赖，和现在的 `[onebot]` 一样。
5. **收敛配置面。** 每个插件对外的字段尽量不超过 8 个，其余用内置默认值。
6. **测试用合成数据。** 从私有端移植测试时，只移植断言和场景，数据重新造。
7. **脱敏闸门。** CI 在现有密钥扫描之外，再查绝对路径、邮箱、疑似账号的长数字。私有标识符的黑名单放在仓库外，由本地推送前的检查使用。

## 4. 阶段

规模为粗估：S 约一天内，M 几天，L 一周以上。

### 阶段 0：修基线

试装报告（`NEWCOMER-TRIAL-2026-11-22.md`）里坏的是 kit 独有的那部分，先修。

| 项 | 规模 |
|---|---|
| 快进后住客不睡觉（时钟引用未同步） | S |
| 真实模型下采购约定不履行（规则兜底被跳过） | S |
| GPT-5 系列连不上的最小修复，错误原因透出 | S |
| 访问令牌展示、端口占用提示、健康检查端点 | S |

验收：试装报告的阻断项清零，现有 737 个测试通过。

### 阶段 1：底座

不加新功能，只让 kit 具备承接插件的能力。

| 项 | 规模 | 主要改动 |
|---|---|---|
| 1.1 插件清单与配置 schema，统一启用开关，加载失败隔离，第三方工具入口 | M | `plugin_api.py`、`cli.py` |
| 1.2 通用设置页与配置存储 | M | `daemon.py`、`onboarding.py`、新增一个控制台页 |
| 1.3 插件钩子：HTTP 路由、周期任务、带上下文的工具调用 | M | `plugin_api.py`、`daemon.py` |
| 1.4 模型层抽象：统一请求构造，参数可配，按任务和住客选模型，重试与切换，记录用量 | M | `chat_agent.py`、`memory.py` |
| 1.5 身份层：谁在说话，渠道账号与身份的映射 | M | 新模块，`memory.py`、`onebot_ws.py` 接入 |
| 1.6 出站：把 `outbox` 接到通道，加统一发送门 | M | `daemon.py`、`plugin_api.py`、`worldkernel/outbox.py` |

验收：
- 现有内置插件全部迁到新清单，行为不变。
- 写一个示例第三方插件包，安装后在网页里完成配置并生效，kit 本身不改一行。
- 新增能力都有测试，全部测试通过。

这一阶段会改动插件接口，建议作为 0.3.0，并在文档里写明迁移方法。

### 阶段 2：纯逻辑能力（A 级）

| 项 | 规模 | 依赖 |
|---|---|---|

| 2.2 群聊行为：回复概率、连发上限、闭麦、睡眠静默 | S | 1.1 |
| 2.3 主动发言：由住客的生活状态触发，带窗口、日上限、最小间隔 | M | 1.6 |
| 2.4 记忆证据与泄露防护：群聊里的陈述不直接记为事实，私聊内容不外泄到群 | M | 1.5 |
| 2.5 完整约定系统，替换 `intents_lite` | M | 1.5 |
| 2.6 提醒、无状态小游戏 | S | 1.3 |

### 阶段 5：反转方向（长期，另行决定）

私有端改为运行 kit 加私有覆盖层。建议在阶段 2 完成后再评估，先拿一个住客做并行试点。在此之前的约定：新功能先写进 kit，再在私有端叠加私有内容。

## 5. 风险与未核实项

| 项 | 说明 |
|---|---|
| 内核一致性 | 只比较了各模块行数，没有逐行对比内容 |
| 记忆证据层 | 私有端仍是默认关闭的试点。kit 可以先做最小版：群聊来源的陈述不直接升级为事实 |
| 上游 QQ agent 的行为 | 结论来自它的 README，没有读源码，也没有实际安装 |
| 规模估算 | 基于文件规模和结构，没有细读私有端全部代码 |
| 标准库约束 | 语音解码等需要第三方包，只能走可选依赖 |
| 真实 QQ 验证 | 需要真实账号，自动化测试覆盖不到 |
| 阶段 1 会破坏现有插件接口 | 目前外部插件应该很少，越早改代价越小 |

## 6. 需要维护者决定

1. 阶段 0 是否现在开始。
2. 阶段 1 是否接受破坏插件接口并发 0.3.0。
3. 身份层是否借这次机会改成与渠道无关（不再只按 QQ 号认人）。这会影响私有端以后回迁。
4. 阶段 5 的方向是否认可。
