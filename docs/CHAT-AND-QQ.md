# 和室友聊天：网页聊天，以及（可选）接 QQ

两条路用的是同一个对话入口（`HouseDaemon.converse`）：同一位室友的私聊记录在网页和 QQ 里是同一份，
回复走同一道「发送前过滤」，约定（"晚上做饭吧"）只认房主说的。

## 路线 A：网页聊天（不需要 QQ，推荐先用这个）

```sh
ai-house up
```

- 完整工作台右侧栏有聊天；也可以直接打开 **`http://127.0.0.1:8780/chat`**，这是一个独立的聊天页，可选「私聊：某位室友」或「小屋群聊」，每 3 秒刷新一次。
- 默认只监听本机，不设令牌就能用。
- 要让别的设备访问（`--host 0.0.0.0`），必须设 `AI_HOUSE_OWNER_TOKEN`（≥16 位）。聊天页会提示输入令牌，令牌只放在请求头里。
- 令牌分档：**私聊**要私聊档（`AI_HOUSE_PRIVATE_TOKEN`）或房主令牌；小屋群聊的读/写分别要读档/写档。
  聊天页只调用 `/api/chat` 和 `/api/chat/roster`，所以只持私聊档令牌也能私聊，但看不了 `/api/state`、也进不了群聊。

## 路线 B：接 QQ（可选，有风险，请先读完）

> **风险**：让程序用一个 QQ 号自动收发消息，可能违反平台的服务条款，账号可能被限制或封禁。
> 请只用你不介意损失的**专用小号**，自己承担后果。本项目不提供 QQ 号、不提供 OneBot 实现，也没有在真实 QQ 上测过：
> 当前版本只用一个模拟的 OneBot 服务器做了自动化测试（`world-kernel/test_p1_onebot.py`）。

你需要自己准备：

1. 一个 QQ 号（给室友用的小号）；
2. 一个 OneBot v11 实现（例如 NapCat、Lagrange 等），并打开它的**正向 WebSocket** 服务（本程序主动去连它）；
3. 本程序的可选依赖：`python3 -m pip install -e ".[onebot]"`（用到 `websockets`，核心仍然零依赖）。

> **Docker 方式接 QQ 说明**：`Dockerfile` 已内置安装 `.[onebot]`，`compose.yaml` 也配置了 `host.docker.internal:host-gateway`。
> 若 OneBot（如 NapCat / Lagrange）跑在宿主机上，在 `.env` 里请把 `ONEBOT_WS_URL` 写成 `ws://host.docker.internal:3001`（不要写 `127.0.0.1`，容器里指向容器自身）。

在 `.env` 里写：

`.env` 里的注释必须单独占一行（不支持写在值后面）：

```ini
# OneBot 的正向 WebSocket 地址；不要在 URL 里带 ?access_token=
ONEBOT_WS_URL=ws://127.0.0.1:3001
# OneBot 端设了令牌就填；只会放在 Authorization 请求头里
ONEBOT_ACCESS_TOKEN=
# 必填：房主的 QQ 号（可写多个，逗号分隔）
ONEBOT_OWNER_QQ=123456789
# 这个 QQ 号扮演哪位室友；不写就是名单里的第一位
ONEBOT_ACTOR=nell
# 允许回话的群号（逗号分隔）；不写 = 不进任何群
ONEBOT_GROUPS=
# 可选限速：同一个聊天里两次处理至少隔几秒 / 一小时最多几条 / 全部聊天合计一小时最多几条
ONEBOT_MIN_INTERVAL_S=3
ONEBOT_MAX_PER_HOUR=30
ONEBOT_MAX_TOTAL_PER_HOUR=120
# 可选：消息带的时间戳比现在早多少秒就当作过期积压、不再回复（0 = 不检查）
ONEBOT_STALE_S=120
```

配置有问题（没写房主、室友名不存在、URL 不是 ws://、数字写错）时 `ai-house up` 会直接报错退出，不会半开着运行。

### 它怎么表现

| 情况 | 行为 |
|---|---|
| 房主私聊 | 回复；和网页里「私聊：该室友」是同一份记录 |
| 其他人私聊 | **不回，也不记录**（只有房主能私聊下指令） |
| 白名单群里 @ 它 | 回复（@ 提问的人）；回话的只有 `ONEBOT_ACTOR` 这一位室友 |
| 白名单群里没 @、@ 了别人、@ 全体 | 不回 |
| 不在白名单的群 | 不回，即使 @ |
| 房主在群里 @ 它 | 当作房主：说的计划会写进约定队列 |
| 群友在群里 @ 它 | 当作「群友」：只是聊天，不会产生约定 |
| 室友正在睡觉 | QQ 上保持安静（网页里能看到「已睡着」的提示） |
| 没配模型，或模型调用失败（程序自己的「演示回复」） | QQ 上保持安静，不发；网页里仍能看到，日志计数 `demo_skipped`。要让 QQ 有回复，先配好模型（见 README） |
| 超过限速 | 直接丢弃，不调用模型，不回复 |
| 房主私聊的限速 | 不受「最小间隔」和「全部合计」限制，只受它自己的每小时上限（`ONEBOT_MAX_PER_HOUR`）约束，超过的会丢弃；房主私聊有单独的队列并优先处理，群里再刷屏也挤不掉它 |
| 积压的旧消息（时间戳早于 `ONEBOT_STALE_S` 秒） | 丢弃，不迟到地回复 |
| 发送失败（回执报错/超时/断线） | 日志里只写错误码，丢弃，不重试 |
| 连接断开 | 自动重连，间隔 1 秒起、翻倍到 30 秒 |

「谁是房主」只看事件里的 QQ 号是否在 `ONEBOT_OWNER_QQ` 里，**不看昵称、群名片或消息内容**；昵称进入提示词前会去掉方括号、
「房主/管理员/系统」之类的字样和长数字串。

### 发送前过滤

每条回复发出前会被检查，命中任何一条就**整条拦下**（网页里会显示「已被拦下」，QQ 上什么都不发，日志只记原因码）：

- 配置里任何令牌/密钥（变量名以 `_TOKEN`、`_SECRET`、`_KEY`、`PASSWORD` 结尾、长度 ≥6）的值；
- 服务器路径（运行目录、`/home`、`/srv`、`/etc`、`C:\…` 等）、`.env`、数据库文件名；
- 与室友设定/系统提示的原文连续重合 20 个字以上；
- 原样的 `[CQ:` 码；
- 群里的回复里出现与房主近期在私聊里说的话连续重合 12 个字以上的片段（室友自己的私聊回复不算，免得常用句子被误拦）。

这是兜底，不是保证：模型换个说法转述私聊内容，过滤是抓不到的。别让室友知道你不想在群里被提起的事。
消息一律以 OneBot 消息段数组发送，不会被当作 CQ 码解析。

### 已知的限制

- 只支持文字：图片、语音、表情在收到时会变成 `[图片]` 之类的占位，不会回图。
- 没有「睡觉后第二天主动问候」之类的主动发言；目前只有被问才回。
- 模型调用期间已释放内核状态锁（`GET /api/state` 不会被慢模型阻塞），写库与步进阶段才短持锁。
- 房主在群里 @ 它，和群友一样走群的队列和限速（只有房主**私聊**才有上面的特殊待遇）；群里连续被 @ 超过 200 条且处理不过来时，多出的会被丢弃。
- 模型出错时，网页里看到的演示回复和房主私聊里说的计划仍会照常记录（只是不发到 QQ），所以「室友记得说过」不一定等于「QQ 上发出去了」。
- 回复先写进聊天记录和约定，再发往 QQ；QQ 发送失败时，房主没收到，但室友的记录里已经说过了。
- 没有「暂停」开关，也没有按天的总上限；限速按聊天（群里房主和群友各算各的）和全部合计两层算，重启后清零。
- 长期记忆库（`MemoryStore`）会持久化保存私聊记忆，并对群聊输出执行跨作用域重叠检查（`check_outbound_leak`），与内存中的 `ReplyGuard` 双重防泄露。
- 网页/MCP 这边，凡是带了写档以上令牌能发消息的人都被当作房主（令牌本身就是身份）。想区分，就别把写档令牌发给别人。
- 私聊档令牌能读所有 QQ 群的聊天记录（含群友发言）。
- 没有在真实 QQ、真实 OneBot 实现上测过。第一次接请用测试群和小号，并观察日志。

## 5. 在线热备与凭据处理

- 运行 `ai-house backup`（或控制台发起备份）会通过 SQLite `Connection.backup()` 对 `runtime/*.db` 生成热备并校验 `PRAGMA integrity_check` 与 SHA-256 `manifest.json`，输出目录默认收口为 `0700`、归档文件为 `0600`。
- 为防止凭据外泄，备份归档**不包含 `.env`**，且会对 `llm_config.json` 与 `plugin_settings.json` 中的 `api_key` / `token` / `secret` 等敏感字段自动脱敏置空；恢复到新环境后，请通过 `.env` 或设置页重新填入对应密钥。
