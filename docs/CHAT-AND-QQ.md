# 和室友聊天：网页聊天，以及（可选）接 QQ

两条路用的是同一个对话入口（`HouseDaemon.converse`）：同一位室友的私聊记录在网页和 QQ 里是同一份，
回复走同一道「发送前过滤」；约定（"晚上做饭吧"）不在聊天当时登记，而是整理记忆时从对话里整理出来，只在房主和住客、住客和住客之间成立。

## 路线 A：网页聊天（不需要 QQ，推荐先用这个）

```sh
ai-house up
```

- 完整工作台右侧栏有聊天；也可以直接打开 **`http://127.0.0.1:8780/chat`**，这是一个独立的聊天页，可选「私聊：某位室友」或「小屋群聊」，每 3 秒刷新一次。
- 默认只监听本机，不设令牌就能用。
- 要让别的设备访问（`--host 0.0.0.0`），必须设 `AI_HOUSE_OWNER_TOKEN`（≥16 位）。聊天页会提示输入令牌，令牌只放在请求头里。
- 令牌分档：**私聊**要私聊档（`AI_HOUSE_PRIVATE_TOKEN`）或房主令牌；小屋群聊的读/写分别要读档/写档。
  聊天页只调用 `/api/chat` 和 `/api/chat/roster`，所以只持私聊档令牌也能私聊，但看不了 `/api/state`、也进不了群聊。

## 路线 B：接 QQ（可选，有风险，请先读完）

> **风险**：让程序用一个 QQ 号自动收发消息，可能违反平台的服务条款，账号可能被限制或封禁。
> 请只用你不介意损失的**专用小号**，自己承担后果。本项目不提供 QQ 号、不提供 OneBot 实现。
> 自动化测试用的是模拟的 OneBot 服务器（`world-kernel/test_p1_onebot.py` 等）；真实 QQ 上只做过两次很窄的验证
> （房主私聊的一问一答，见 [DEPLOY.md](DEPLOY.md) 开头的「现状」；群里被 @ 后回话与私聊内容的拦截，见 [LONGRUN-2026-11-23.md](LONGRUN-2026-11-23.md) 第 9 节），图片语音、掉线重连和长时间运行都还没在真号上试过。

你需要自己准备：

1. 一个 QQ 号（给室友用的小号）；
2. 一个 OneBot v11 实现（协议端），并打开它的**正向 WebSocket** 服务（本程序主动去连它）。协议端需要你自己取得：本项目不提供、不分发任何协议端，也不绑定某一家，只要求它满足 [DEPLOY.md](DEPLOY.md) 第 2.1 节列出的接口；
3. 本程序的可选依赖：`python3 -m pip install -e ".[onebot]"`（用到 `websockets`，核心仍然零依赖）。

> **Docker 方式接 QQ 说明**：`Dockerfile` 已内置安装 `.[onebot]`，`compose.yaml` 也配置了 `host.docker.internal:host-gateway`。
> 若 OneBot 端跑在宿主机上，在 `.env` 里请把 `ONEBOT_WS_URL` 写成 `ws://host.docker.internal:3001`（不要写 `127.0.0.1`，容器里指向容器自身）。
> 协议端也在 Docker 里、后台常驻（systemd / compose）以及协议端那边要开哪些设置，见 [DEPLOY.md](DEPLOY.md)。

在 `.env` 里写：

`.env` 里的注释必须单独占一行（不支持写在值后面）：

```ini
# OneBot 的正向 WebSocket 地址；不要在 URL 里带 ?access_token=
ONEBOT_WS_URL=ws://127.0.0.1:3001
# OneBot 端设了令牌就填；只会放在 Authorization 请求头里
ONEBOT_ACCESS_TOKEN=
# 必填：房主的 QQ 号（可写多个，逗号分隔）
ONEBOT_OWNER_QQ=123456789
# 这个 QQ 号扮演哪位室友；不写就是名单里的第一位
ONEBOT_ACTOR=nell
# 允许回话的群号（逗号分隔）；不写 = 不进任何群
ONEBOT_GROUPS=
# 可选限速：同一个聊天里两次处理至少隔几秒 / 一小时最多几条 / 全部聊天合计一小时最多几条
ONEBOT_MIN_INTERVAL_S=3
ONEBOT_MAX_PER_HOUR=30
ONEBOT_MAX_TOTAL_PER_HOUR=120
# 可选：消息带的时间戳比现在早多少秒就当作过期积压、不再回复（0 = 不检查）
ONEBOT_STALE_S=120
# 可选：只听不发（见下面的「只听不发（影子并行）」）；只能写 1、0 或留空
ONEBOT_LISTEN_ONLY=
# 可选：她一轮对话里最多发几条（send_message 工具的次数；0 = 这一轮不限条数；负数、不是整数、大于 1000 的值一律按默认 3）。群里默认 3，私聊默认 3；每小时的上限不受它影响
AI_HOUSE_MAX_SENDS_PER_TURN_GROUP=3
AI_HOUSE_MAX_SENDS_PER_TURN_PRIVATE=3
```

配置有问题（没写房主、室友名不存在、URL 不是 ws://、数字写错）时 `ai-house up` 会直接报错退出，不会半开着运行。

配好之后可以先检查连通（只问登录状态，不发任何消息）：

```sh
ai-house doctor --onebot-ping
```

### 它怎么表现

| 情况 | 行为 |
|---|---|
| 房主私聊 | 回复；和网页里「私聊：该室友」是同一份记录 |
| 其他人私聊 | **不回，也不记录**（只有房主能私聊下指令） |
| 白名单群里 @ 它 | 回复（@ 提问的人）；回话的只有 `ONEBOT_ACTOR` 这一位室友 |
| 白名单群里没 @、@ 了别人、@ 全体 | 不回 |
| 不在白名单的群 | 不回，即使 @ |
| 房主在群里 @ 它 | 当作房主：和住客约好的事，在整理这段对话的记忆时会记成约定 |
| 群友在群里 @ 它 | 当作「群友」：只是聊天，不会产生约定（约定只在房主和住客、住客和住客之间成立，按号码认人，不看群名片） |
| 室友正在睡觉 | QQ 上保持安静（网页里能看到「已睡着」的提示） |
| 没配模型，或模型调用失败（程序自己的「演示回复」） | QQ 上保持安静，不发；网页里仍能看到，日志计数 `demo_skipped`。要让 QQ 有回复，先配好模型（见 README） |
| 超过限速 | 直接丢弃，不调用模型，不回复 |
| 房主私聊的限速 | 不受「最小间隔」和「全部合计」限制，只受它自己的每小时上限（`ONEBOT_MAX_PER_HOUR`）约束，超过的会丢弃；房主私聊有单独的队列并优先处理，群里再刷屏也挤不掉它 |
| 积压的旧消息（时间戳早于 `ONEBOT_STALE_S` 秒） | 丢弃，不迟到地回复 |
| 发送失败（回执报错/超时/断线） | 日志里只写错误码，丢弃，不重试 |
| 连接断开 | 自动重连，间隔 1 秒起、翻倍到 30 秒 |

「谁是房主」只看事件里的 QQ 号是否在 `ONEBOT_OWNER_QQ` 里，**不看昵称、群名片或消息内容**；昵称进入提示词前会去掉方括号、
「房主/管理员/系统」之类的字样和长数字串。

### 发送前过滤

每条回复发出前会被检查，命中任何一条就**整条拦下**（网页里会显示「已被拦下」，QQ 上什么都不发，日志只记原因码）：

- 配置里任何令牌/密钥（变量名以 `_TOKEN`、`_SECRET`、`_KEY`、`PASSWORD` 结尾、长度 ≥6）的值；
- 服务器路径（运行目录、`/home`、`/srv`、`/etc`、`C:\…` 等）、`.env`、数据库文件名；
- 与室友设定/系统提示的原文连续重合 20 个字以上；
- 原样的 `[CQ:` 码；
- 群里的回复里出现与房主近期在私聊里说的话连续重合 12 个字以上的片段（室友自己的私聊回复不算，免得常用句子被误拦）。
  只有一个例外：你在 `AI_HOUSE_MEMORY_LEAK_FREE_GROUPS` 里列出的群，对「房主私下跟这位室友说的话」不查这一条，见下面「私聊记忆进群」；
  上面其余几条在列出的群里照样检查。

这是兜底，不是保证：模型换个说法转述私聊内容，过滤是抓不到的。别让室友知道你不想在群里被提起的事。
消息一律以 OneBot 消息段数组发送，不会被当作 CQ 码解析。

### 已知的限制

- **群里发图片、语音、表情包要有出处**：只有内置工具（文生图、语音合成、表情包）刚做出来、并登记了“给哪个聊天、用什么文字做的”的内容才能发进群；发之前会拿那段文字再过一遍拦截和私聊泄露检查，换了群、换了内容或重启过（登记在内存里，重启就没了）都发不出去，日志里写原因。房主私聊不要求。目前没有开放给第三方插件的登记接口（`media_provenance.register_for_tool` 只有内置的图片、语音、表情包工具在调用），所以第三方插件的图片、语音暂时发不进群。
- 私聊泄露检查本身出错（没有记忆库、查不了）时，**不在泄露豁免名单里的群一律不发**，原因 `privacy_check_unavailable`，不记额度；在名单里的群照发并记一行日志。
- 群被闭麦时，提醒和主动发言也不会发出。**提醒**先等着，解除闭麦后补发，等多久都行（没有过期时间），所以几个小时前的提醒会在解除后迟到发出；**主动发言**等满 30 分钟还没发出去就作废，解除闭麦后不会再补发。
- 发件箱里发往群（含网页群聊）的消息，没带发言人、或发言人不是住客的，会被拒绝（`privacy_check_unavailable`）；以前这种消息会跳过私聊泄露检查直接发出去。内置的提醒和主动发言一定带发言人，只有手写的或第三方插件塞进去的消息受影响；泄露豁免名单里的群除外。
- 默认只处理文字：图片、语音在收到时会变成 `[图片]` 之类的占位。启用「看图」「语音」「文生图」「表情包」等可选插件（默认关闭，见设置页）后，才会理解收到的图片和语音，并把生成的图片、语音随回复发出。
- 主动发言由可选插件「主动发言」提供，默认关闭；不启用时只有被问才回。
- 模型调用期间已释放内核状态锁（`GET /api/state` 不会被慢模型阻塞），写库与步进阶段才短持锁。
- 房主在群里 @ 它，和群友一样走群的队列和限速（只有房主**私聊**才有上面的特殊待遇）；群里连续被 @ 超过 200 条且处理不过来时，多出的会被丢弃。
- 模型出错时，网页里看到的演示回复和房主私聊里说的计划仍会照常记录（只是不发到 QQ），所以「室友记得说过」不一定等于「QQ 上发出去了」。
- 回复先写进聊天记录，再发往 QQ；QQ 发送失败时，房主没收到，但室友的记录里已经说过了。约定不在这一步登记，而是稍后整理记忆时从对话里整理出来。
- 群里可以由房主让住客闭麦和恢复。发送门对普通回复和主动发言分别设有每小时、每天的上限，两者互不挤占，计数持久化保存，重启后不清零；被上限拦下的回复不会另发提示，原因记在通道状态和日志里。通道自身的限速（按聊天、全部合计两层）仍在，重启后清零。
- 长期记忆库会持久化保存私聊记忆。默认情况下，群里的回复发出前要过两道私聊泄露检查：记忆库的出站检查（`check_outbound_leak`：回复重复了这位室友某条私聊记忆、或某句还没整理的私聊原话一半以上的字，就拦；接了向量服务时，意思很接近且字面也有相当重合的也拦）和内存中的 `ReplyGuard`。对 `AI_HOUSE_MEMORY_LEAK_FREE_GROUPS` 里列出的群，这两道里「私聊内容」那一条都不再拦（见下一节）。
- 网页/MCP 这边，只有房主档和私聊档令牌会被当作房主；写档令牌能发消息，但身份是访客。
- 私聊档令牌能读所有 QQ 群的聊天记录（含群友发言）。
- 真实 QQ 上验证过两次：房主私聊的文字收发（2026-11-23，一次）；两个群里被房主 @ 后的文字回话，以及“私聊记忆进群”两个开关（2026-11-24，7 轮，见 [LONGRUN-2026-11-23.md](LONGRUN-2026-11-23.md) 第 9 节）。别的群友发问、图片和语音、掉线后的重连与补发、长时间运行、风控下的表现都没有在真号上试过。第一次接请用测试群和小号，并观察日志。
- 小屋里还没有住客时（还没走网页向导，或刚重置过世界）QQ 消息不回，日志里有一行提示；建好住客后不用重启。
- 同一个 QQ 号的协议端上如果还接着别的机器人程序，两边都会收到消息并各自回复。一个号只接一个会回话的程序。

## 只听不发（影子并行）

`ONEBOT_LISTEN_ONLY=1`：QQ 照常**收**，但**一个字都不往 QQ 写**。用途是新旧两套程序并行跑：旧的继续回话，新的在旁边听着、照常想怎么回，把“本来会发什么”记下来，对着看，满意了再切过去。

```ini
# 只听不发：只能写 1（开）、0 或留空（关）；写 true、yes 之类一律启动失败（宁可起不来，也别让本想静默的通道发出去）
ONEBOT_LISTEN_ONLY=1
# 只对这一个 QQ 通道生效；网页聊天完全照常。只能从环境变量设，设置页里存的配置改不了它；改了要重启
```

**它做什么**

- 收消息、查白名单、走对话、过发送门，一步不少，所以“会不会被拦、会不会超限”都按真的来；到最后一步“写进 QQ”才停下。
- **写 QQ 的那一处**默认全部拒绝（发送接口、发送门、旧的回复补发、第三方插件的 `authorize_send` 都一样），收消息的那条连接被包了一层，直接往上写会报错。所以不是“漏了一个地方”的问题。
- 本来会发的内容记在一张影子记录里：时间、路径（直接回复 / 提醒和主动发言）、发给谁、发送门的结论（`allowed` / `blocked:原因` / `limited:原因`）、是哪几条收到的消息引起的（可以和正在运行的那套程序的记录对上）。**被拦下的草稿只记原因和字数，不记原文**；图片、语音只记种类、sha256 和大小，不记内容。
- 读它：`GET /api/listen-only`（房主档令牌），或者在控制台运维页的“消息通道”一行看到通道名后面标着“（只听不发）”。`ai-house doctor` 也有一行 `onebot_listen_only`。启动时日志里有一行大写的提示。
- 额度照算：影子的发送记在带标记的单独几行里，每小时、每天的上限按“假装发出去了”模拟；它们不会占真的额度，关掉只听不发时真额度从零开始。
- 启动时，开机前已经存着、还没发出去的回复（`reply_ready`）会被关掉，不会等开关一关就一股脑发出去。提醒、主动发言走发件箱：只听不发时它们会被“收下”（影子记录里有一行），不会在以后补发。

**记忆怎么处理**

- 收到的话照常记（房主说了什么，她是知道的）。
- 她想好的回复**不当成她说过的话**：聊天里存成单独一类（`shadow`，不进最近几句对话给她看），记忆整理只收到房主那一句、回复为空。否则她会“记得”自己说过一句其实没人听见的话，并据此接着聊。
- 网页聊天不受影响：网页上说的话照常回、照常记。

**要知道的事**

- “只听”不等于“没有副作用”：生成图片、语音合成这些付费调用照样发生；提醒照样被建立；主动发言照样会去请求模型。想完全不花钱，别开这些。
- 它只保证 **QQ 这一边不写**。别的通道（网页聊天、别的插件自己的传输）不在它管的范围里。
- 影子记录最多保留 5000 条 / 14 天，放在通道自己的运行库里，会被备份带上。发件箱里被挡住等着的消息（闭麦、安静时段、每小时上限）每个“消息编号 + 原因”只记一行，之后每次重试都不再重复记；原因变了、最后放行、或被拦下，还会再记一行。
- 额度是模拟的：草稿也会像真回复一样推进群里“连续回复”的计数。
- 用 agent-shell 引擎时，引擎自己的会话历史会不会留下她没发出去的草稿，没有验证过。

**读回账号真正发出的回复（可选，`ONEBOT_LISTEN_ONLY_OBSERVE=1`）**

并行时真正回话的是旧程序，她自己想好的回复只是草稿，所以房主托她的事（“明天帮我买盒红茶”）永远等不到她的“好呀”，约定也就记不成。想看新程序能不能把约定记对，可以让它去读旧程序真的发出去的那句：

```ini
# 只能和 ONEBOT_LISTEN_ONLY=1 一起开；只能写 1、0 或留空，别的值、或者没开只听不发就开它，都会启动失败
ONEBOT_LISTEN_ONLY=1
ONEBOT_LISTEN_ONLY_OBSERVE=1
```

- 每处理完一条收到的消息（私聊或群），后台线程隔约 10 秒查一次聊天记录，最多等 120 秒：找这个账号自己发的、不早于那条消息的话；找到后再多等一次，把后面的几个气泡也收进来（最多 5 条，换行连起来；中间有别人的新消息就到此为止）。图片、语音等照常写成 `[图片]`、`[语音]` 这样的占位。不会卡住收消息。
- **只读，只用两个接口**：私聊 `get_friend_msg_history`，群 `get_group_msg_history`（NapCat 的扩展接口）。写 QQ 的那一处仍然默认全部拒绝，只把这两个读接口放进一张明确的白名单；发送、撤回、各种 `set_*` 以及别的任何接口都照旧被拒。没开这个开关时，这两个接口也被拒，行为和以前完全一样。
- 读到的话**算她说过的话**：聊天里存成一行 `observed`（和正常回复一样会进最近几句对话给她看），记忆整理拿到“房主那句 + 她这句”，所以约定能照常记成。她自己的草稿那一行（`shadow`）不变。
- 影子记录里多一行 `observe`：`observed:几条`（读到了几个气泡）、字数，或 `observe_none`（等满了没等到，这时和以前一样，回复为空）、`observe_error:原因`（读记录失败）。**只记条数和字数，不记原文。**
- 读记录失败（协议端不支持这两个接口、超时、返回错误）只在日志里记一行，这一轮按以前的做法（回复为空），不重试。
- 前提是协议端支持这两个接口，且账号自己发的消息能在聊天记录里查到；协议端不用开 `reportSelfMessage`，这里也不依赖它。

## 私聊记忆进群（可选，两个互相独立的开关，默认都关）

默认情况下，住客在任何群里都取不到房主私下对她说的话，房主在群里问「你知道我最近的打算吗」，她只能答不知道。
要改，有两个开关，各管一件事：

```sh
# 开关一：能不能想起来。1 才开。开了以后，住客在任何群里都想得起她自己和房主的私聊记忆
AI_HOUSE_MEMORY_PRIVATE_IN_GROUPS=1
# 开关二：能不能说出来。列出的群发送前不再拦私聊内容。逗号分隔，全局一份，可以写：
#   group             小屋网页里的群
#   qq-group:<群号>   QQ 群，群号是纯数字，要和 ONEBOT_GROUPS 里的一致
AI_HOUSE_MEMORY_LEAK_FREE_GROUPS=group
```

- 开关二里写法不对的项（以 `private` 开头的、`qq-group:` 后面不是纯数字的、只写一串数字的）会让 `ai-house up` 报错退出，
  `ai-house doctor` 也会指出；程序自己解析时遇到这样的项一律当没写。空格和重复项没关系。
- 和其它记忆设置一样，启动时读一次，改了 `.env` 要重启才生效。
- `qq-group:<群号>` 只管那个 QQ 群，不会连带管网页里的群；反过来也一样。

### 四种组合

| 开关一 | 开关二 | 住客在群里的表现 |
|---|---|---|
| 关 | 空 | 默认。想不起私聊内容；复述了会被拦下 |
| 开 | 空 | 在任何群里都想得起，但提示里要求她别说出来、也别暗示；她要是照说了，回复仍被拦下 |
| 关 | 列了群 | 想不起私聊内容（所以不会主动提）；列出的群发送前不查私聊内容这一条，别的群照拦 |
| 开 | 列了群 | 列出的群里想得起，也可以自然地提；没列出的群里想得起，但不许说，说了照样被拦下 |

要达到「住客在小屋群里能提房主私下说过的事」，要写 `AI_HOUSE_MEMORY_PRIVATE_IN_GROUPS=1` 加 `AI_HOUSE_MEMORY_LEAK_FREE_GROUPS=group`。

### 开关一管什么

- 住客 A 在群里回想事情时，除了原来能想起的，还能想起**她自己**和房主的私聊记忆：不分类型、不分可信级别、也不看是谁在问。
  别的住客和房主的私聊，她始终看不到。
- 房主刚在私聊里说、还没来得及整理成记忆的话，也会带上（只取房主说的陈述句，且和当前问题有关）。
- 房主只问一句没有具体内容的话（「你还记得我跟你说过的事吗」「你知道我最近的打算吗」）时，和私聊里一样，会带出最近几条私聊记忆和刚说的话。
- 给模型看的记忆里，私聊来的条目标着「私密」。只在确实带出了这类条目时，才多一行说明：开关二没列这个群，说明是「心里知道就好，别说出来，也别暗示」；
  列了这个群，说明是「这里是小屋自己的群，想提可以自然地提」。她的 `search_memory` 工具返回的文本用同一行说明。
  还没整理成记忆的私聊原话每一行自带同样口径的标签（没列的群「你知道，但别在群里说出来」，列了的群「想提可以自然地提」）。
- 带出了私密条目，就不会再同时告诉她「你不记得」。
- 写入不变：群里说的话，整理出来仍然是这个群的群记忆；而且在这类群里整理出的记忆不会存成「共同」（`shared`）范围。
  读到私聊记忆不等于能改它：在群里，住客不能改写或作废私聊范围的记忆。

### 开关二管什么

只管发出去的那一步和说明的语气，不管能不能想起：

- 列出的群：记忆库的出站检查对这个群不查；`ReplyGuard` 的「与房主私聊原话连续重合 12 字以上」这一条不查。
  这一条的豁免只对「房主私下对这位住客说的话」成立：房主对别的住客说的话，这位住客在群里说出来仍然会被拦。
  其余检查（密钥、服务器路径、人设原文、原样 CQ 码）在任何群里都照常。
- 没列出的群：两道检查照旧硬拦。开关一打开之后，这一点尤其要紧。

### 列出的群里形成的群记忆

列在开关二里的群，里面说过的话照常被整理成这个群的群记忆，其中可能带着住客在那里提起的私聊内容。这些群记忆**没有额外的围栏**：

- 没开 `AI_HOUSE_MEMORY_UNIFIED_GROUPS`（默认）：群记忆各群分开，别的群读不到。
- 开了 `AI_HOUSE_MEMORY_UNIFIED_GROUPS=1`（群记忆跨群可见）：列出的群里形成的群记忆，别的群（包括没列出的群）也读得到，
  而且发送前的检查只拿回复和**私聊**记忆比，不和群记忆比，所以住客在别的群里说出这条群记忆不会被拦。

也就是说：同时开着“群记忆跨群可见”和开关二时，私聊里的事可能经由“在列出的群里说过、被记成群记忆”这条路，出现在别的群里。
介意这一点，就不要把这两样同时打开。（更早的版本在这里有一道围栏；记忆改为与维护者自己部署共用同一份代码后，按那边的现行行为去掉了。）

### 要先想清楚的风险

- 开关一打开后，没列出的群里「别说」只靠提示加发送前的检查兜底。检查看的是字面重复（接了向量服务时再加上意思很接近的）；模型换个说法、只提其中一个词（比如只说出那样东西的名字），检查是抓不到的。
- **列出的群里任何人问起，住客都可能说出房主私下说过的事**，不只房主本人问。她分不清问的人该不该知道，提示里只有一句让她自己掂量。
- 小屋自己的群里其他住客也在场：他们会听到，并且把听到的记成这个群的群记忆。
- QQ 群里除了你，还有别的人，他们看得到她说的每一句。已经说出口的话收不回来。
- 发送前的过滤只是兜底。别把人多、不熟的群列进开关二。
- 公开相册、日记配图、联网搜索、语音等插件用的泄露检查没有带群频道，仍按「没列出」处理，不会放行私聊内容。

## 5. 备份、恢复与凭据处理

**备份**

- 运行 `ai-house backup`（或在控制台发起备份）会通过 SQLite `Connection.backup()` 对 `runtime/*.db` 生成热备，校验 `PRAGMA integrity_check`，并在 `manifest.json` 里记录每个文件的 SHA-256。自动创建的备份目录权限为 `0700`，归档文件为 `0600`；你自己指定的输出目录不会被改权限。
- 归档包含数据库、配置 JSON、自定义世界包（`custom-pack/`）和媒体（`media/`，含相册和日记配图）。媒体较多时归档会比较大，超过 512 MiB 会给出提示但不会中止（`--warn-size-mb` 或环境变量 `AI_HOUSE_BACKUP_WARN_MB` 可调）。
- 旧备份按真实时间清理，与小屋里的虚拟时间无关。

**归档里不会有的东西**

- `.env`、`*.key`、`*.pem` 不进归档。
- 归档内所有 JSON 都按键名递归脱敏：键名（不分大小写）含 key、token、secret、password、passwd、auth、authorization、cookie、webhook 的值会被置空；`max_tokens`、`keywords`、`author` 这类明显不是密钥的键不受影响。URL 里的 `user:pass@` 和 `?token=`、`?key=` 参数同样去掉。
- 自定义世界包和媒体目录里，名字恰好就叫 `key` 或 `auth` 的字段被视为普通标识，不会被清空。
- `manifest.json` 只记录哪些字段被脱敏（字段路径），不记录任何值。

**恢复**

- 先停掉正在运行的小屋，再执行 `ai-house restore <归档>`。检测到同一运行目录上有存活的进程时，恢复会拒绝执行，并且不做任何改动。
- 恢复是整体生效的：先在临时目录里解包并逐文件校验，全部通过后再替换；中途失败会回滚到恢复前的状态。
- 归档里被脱敏的字段，如果目标目录里同一位置已有值，会保留现有值；没有现有值的，命令结束时会列出“以下密钥需要重新填写”（只显示字段路径）。恢复到新机器时，请在设置页或对应的 JSON 里补填，并自行准备 `.env`。
- 归档成员路径含 `..`、绝对路径、符号链接、硬链接、设备文件或点开头的敏感文件名时，整个恢复会被拒绝。
- 由更新的主/次版本程序创建的归档会被拒绝并提示升级，`--force` 可以强制；没有版本信息的旧归档可以恢复，会有一条提示。
